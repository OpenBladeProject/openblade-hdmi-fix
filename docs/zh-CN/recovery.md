# 恢复与故障处理

[English](../recovery.md) | 简体中文 | [Русский](../ru-RU/recovery.md)

在应用验证 Patch 或 Restore 成功前，保持显示器与笔记本的 HDMI 连接断开。

取消管理员权限提示后，应用会刷新已保存的显示器状态。
操作中断时，原始备份仍然可用。选择同一条连接，在按钮可用时选择 **Restore（恢复）**。
如果操作在停止前创建了空的覆盖注册表项，也可用此方法处理。

Restore 不可用时，请保留备份文件夹，并使用 **Copy details（复制详情）**报告问题。
其他工具改过的 EDID 或覆盖值无法自动恢复。
请先用修改它们的工具恢复原始状态。在已保存数据得到验证前，不要再次尝试应用补丁。

请使用创建备份的 Windows 账户。
应用将备份保存在解压文件夹之外，下载另一份应用不会丢失备份。
备份缺失或无效时，无法自动恢复已安装的覆盖值。

未完成操作的备份保留在主备份文件夹中。
已完成的备份保存在账户专属的 `history-` 文件夹。
活动备份达到 512 个上限后，应用会禁止添加新补丁，但仍可使用 Restore。
如果存在其他账户的备份，请先用该账户完成恢复，再应用新补丁。
你自己的备份仍可用于 Restore。

如果应用显示 **Saved capabilities changed（已保存的功能数据已变化）**，
说明已安装的覆盖值与备份匹配，但 Windows 为该连接保存了不同的 EDID 数据。
请保留备份文件夹，并复制详情，在报告问题时说明这一变化。
在显示器身份和已保存数据得到验证前，Restore 会保持不可用。

不要上传备份 JSON、临时备份文件、原始 EDID 或注册表导出文件。
这些文件可能包含显示器序列号及能识别这台计算机的信息。复制的诊断报告会省略这些字段。

如果重新连接仍导致显示系统崩溃，请断开显示器的 HDMI 连接。
通过笔记本内置屏幕恢复操作，再打开应用检查已保存连接。
应用不会替你连接显示器、重启显示设备、重置 GPU 或更改显示模式。

<a id="saved-entry-unavailable"></a>

## 已保存条目不可用

保持 HDMI 连接断开。选择已保存连接，阅读卡片上的原因。
打开 **Backups and diagnostics（备份与诊断）**，选择 **Copy details（复制详情）**，
报告问题时附上该报告和显示器的精确型号。

报告会区分已保存功能数据缺失或不完整、数据无效、显示器身份不匹配、
访问被拒绝，以及无法识别的覆盖值。
查明原因前，请保留所有现有覆盖值和原始备份。
报告不含原始 EDID、序列号、设备实例 ID 和本地路径。

报告包含已保存 EDID 的长度、声明的块数、标头和身份检查、
每个完整块的校验和、可读的 HDMI 功能字段及覆盖状态。
它还包含同一显示器的其他已保存连接，因此无需重新连接或逐条检查，
就能发送一份完整报告。从无效数据中读取的功能字段仅是观察结果，不会启用 Patch。

显示器可以通过 HDMI Forum 扩展块数量覆盖声明（HF-EEODB）声明额外的 EDID 块。
应用会检查该声明、验证每个块，并在应用补丁时保留额外的块。
较长的已保存条目若没有有效声明，仍会显示为不可用。
复制的详情会显示基础块数和实际生效块数。

扩展块数量规则参考
[Linux DRM EDID 读取器](https://raw.githubusercontent.com/torvalds/linux/master/drivers/gpu/drm/drm_edid.c)
和 [edid-decode 验证](https://raw.githubusercontent.com/gjasny/v4l-utils/master/utils/edid-decode/parse-cta-block.cpp)：
在第一个 CTA 扩展的开头只能有一个三字节声明，且保存长度必须与声明的块数匹配。
应用要求该声明使用 CTA 修订版 3 或更新版本，并要求每个已保存块通过校验和检查。

<a id="reporting-repeated-blanking-after-patching"></a>

## 报告应用补丁后反复黑屏

如果笔记本仍可使用，但外接显示器反复黑屏，请在笔记本屏幕上打开应用，
选择出现问题的已保存连接，依次选择 **Refresh（刷新）**和 **Copy details（复制详情）**。
读取诊断不会更改显示设置，也不会重新安装补丁。

报告包含笔记本型号、Windows 构建版本、当前存在的显卡及其 Windows 驱动版本，
以及已保存的 EDID 显示器名称。
如果能将所选连接准确匹配到活动显示路径，报告还会包含其当前模式、连接类型、HDR 状态，
以及采集时 NVIDIA VRR 的功能支持、请求状态、启用状态和即时活动状态。
即使 VRR 已启用，采集时也可能没有实际运行。

断开 HDMI 连接后仍可收集系统和已保存的显示器信息。
对于已断开的条目，或应用无法精确匹配的连接，实时设置不可用。
不支持或失败的驱动查询显示为未知。
这些查询无法读取显示器自身菜单中的 Adaptive Sync 设置。
EDID 名称可能经过缩写，要确认完整的市售型号，可能仍需查看显示器的“关于”页面。

报告时请说明笔记本是否仍然崩溃、黑屏频率，以及已测试的刷新率。
保留原始备份。没有进一步证据时，不要因为反复黑屏就再应用一次补丁或禁用 DSC。

<a id="interrupted-connection-recordings"></a>

## 中断的连接记录

应用会在记录过程中保存基线报告和每条时间线记录。
如果笔记本崩溃，请在重启 Windows 后重新打开应用。
应用会用已保存的有效条目生成包含部分结果的诊断 ZIP，并提供 **Open recording folder（打开记录文件夹）**。
它不会继续记录，也不会重新连接显示器。

恢复后的摘要会标明这是一次中断会话。
最后一次写入可能缺失或不完整；恢复过程会保留此前可读的条目和原始文件。
如果崩溃发生在收集前，Windows 事件和私密显示日志可能不可用。
从未写入存储的数据无法恢复。

**Built-in display（内置显示屏）**表示当前连接的笔记本屏幕。
**Stale built-in display entry（旧的内置显示条目）**表示与该屏幕匹配但不活动的已保存记录。
使用此临时修复时，请选择外接 HDMI 显示器。两种内置屏幕条目都不是 HDMI 补丁目标。
