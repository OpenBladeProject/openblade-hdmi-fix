<a id="software-checks"></a>

## 软件检查

显示器的功能数据结构满足要求时，此配置会限制两个最大 HDMI FRL 字段，并保持 DSC 启用。
不限制显示器品牌和型号，应用在修改前会显示尚未验证的警告。
高刷新率、HDR、VRR 和 HDMI 音频尚未通过本应用验证。

本地检查覆盖：

- 完整 EDID 解析、块校验和、EDID 与实例的制造商/产品身份、结构化 Forum 功能查找、
  DSC 准入、不支持的布局，以及两个字段和受影响校验和之外的字节保持不变。
- 持久备份的先后顺序、修改前状态变化、写值前后的中断、恢复、其他工具的覆盖值、
  错误的显示器实例、无效注册表目标和损坏备份。
- WPF 窗口构造、正常和最小宽度下的合成数据渲染，以及展开的诊断区域。
- 自包含的 Windows x64 负载。

Release 解决方案构建完成，无警告和错误，325 项测试通过（核心 123 项，桌面 202 项）。
回归检查覆盖其他显示器制造商、精确 EDID 与实例绑定、无效制造商编码、跨型号补丁/恢复、
其他显示器的严格恢复、CTA 零偏移填充、版本 1 备份恢复、512 个活动备份的边界、
私密账户记录和缓存 EDID 变化。
临时 Git 测试仓库验证打包会拒绝未提交源码和打包期间的提交变化，同时允许被忽略的构建输出。
开发机器的只读扫描返回了已连接的内置屏幕和一条曾连接的已保存记录，没有 G93SC 条目。
正常/最小宽度和展开状态的预览截图使用合成数据；实际扫描未应用覆盖。

测试数据为合成数据，不含真实显示器序列号。
渲染预览不能验证特定机器的缓存 EDID 是否可用、UAC、已安装环境的注册表权限，
或实际 HDMI 链路协商。

<a id="physical-validation-pending"></a>

## 待完成的物理验证

将某版本标为已验证前，请记录精确源码提交、笔记本型号/SKU、GPU、Windows 和显卡驱动版本、
显示器型号/固件、线缆、端口/适配器，以及所选的已保存连接。
可识别身份的原始数据应保密。

断开显示器的 HDMI 连接后，检查实际历史条目、保存已确认的原始状态，
重新通过准入检查后应用一次类型化补丁，并通过回读验证覆盖值。
测试时须有人在场，重新连接并检查显示器的预期分辨率和刷新率、HDR、
通过显示器反馈确认的 VRR、HDMI 音频，以及代表性使用中的稳定性。
记录实际测试范围。断开连接，恢复原始覆盖值，并通过回读验证恢复。
仅在初始测试成功后，再确认重启和重新连接行为。

软件构建或预览不授权实际补丁写入、UAC 修改、重新连接或睡眠/恢复测试。
睡眠/恢复测试要求在执行前立即取得在场用户的新批准。

<a id="connection-diagnostics"></a>

## 连接诊断

测试覆盖 Windows 和 NVIDIA ABI 尺寸、精确显示实例绑定、歧义路径、
分别记录的 HDR/VRR 状态、未知查询、已断开条目、独立读取失败和复制报告的隐私保护。
只读集成扫描记录了开发笔记本、Windows 构建版本、两块 GPU 的驱动版本，
以及内置屏幕当前的模式/HDR。
NVIDIA 查询无法解析该内置目标，因此 VRR 字段为未知。没有尝试修改。

用户测试 0.2.5 后发现补丁能够应用，笔记本不再整机崩溃，
但 G95 画面在 120 Hz 和 240 Hz 下仍大约每五秒黑屏一次，使用和空闲时均如此。
后续用户测试发现，在显示器上启用 Adaptive Sync 可稳定画面，并可在 240 Hz 下运行基准测试。
这不能确定根本原因。稳定性调查见
[议题 #6](https://github.com/OpenBladeProject/openblade-hdmi-fix/issues/6)。
新增诊断用于收集证据，并未解决黑屏问题。
审核后的跟进覆盖无法解析的活动路径错误、包括 DisplayPort USB 隧道在内的已知连接器类型，
以及两个可选读取器的可恢复故障隔离。
故障注入验证了一个读取器失败时仍保留另一读取器的数据，且刷新失败不会复用旧的实时快照。
致命内存错误和本机内存损坏不会伪装成普通的数据缺失。

<a id="connection-recording-checks"></a>

## 连接记录检查

记录器测试覆盖从断开状态基线变为精确的已连接实例、同型号实例隔离、
失败或歧义读取显示未知连接状态、持久保存黑屏/设备/显示标记、
可选证据收集失败、读取器卡住时及时取消，以及与上一次记录尚未结束的读取隔离。
事件测试覆盖范围受限的服务器端查询、安全元数据解析、无法访问的日志、截断，
以及固定的显示日志参数。

只读 WPF 集成检查测试了 Start、Mark blackout、Stop and save，以及记录期间关闭窗口。
采集期间禁用 Patch、Restore、Refresh 和显示器选择，之后恢复。
停止和关闭都生成了部分 ZIP，其中仅含允许的四个报告文件；
私密 Windows 显示日志单独采集。没有调用 Patch 或 Restore。
已检查正常宽度、最小宽度记录状态和展开的诊断预览。

这些检查没有连接出现问题的显示器。
Windows 日志和显示快照不能确认 HDMI FRL/DSC 协商或实际黑屏，
这仍需由用户在场记录。

Claude 在 `05bbdf1` 审核了记录功能。
后续回归保证通知突发时仍为黑屏标记留有容量、
达到时间线上限后保留终止记录和已接受的标记、
读取期间保持标记时间戳顺序、报告保存阶段、保留用户输入的标点，
并在无法创建私密日志文件夹时仍保留 ZIP。
记录器准备工作现已移到 WPF 调度线程之外。
只读 GUI 检查还通过缩短测试时长和延迟可选日志采集，测试了自动完成；
保存期间禁用标记和停止操作。

<a id="scdc-recording-checks"></a>

## SCDC 记录检查

本机传输测试验证了公开 NVAPI 接口 ID、64 字节 x64 I2C 结构、
三个允许读取的寄存器、FRL 速率解码、版本和返回数据验证、目标变化、
接口缺失和读取失败。合成委托用于调用本机函数签名，不发送实际 I2C 事务。
记录器回归覆盖仅查询所选实例、跳过有歧义/非 HDMI 目标、保留模式/HDR/VRR 证据、
已脱敏的 SCDC JSON，以及实际 DSC 活动保持未知。

Release 构建完成，无警告和错误。
只读 WPF 测试使用合成的所选实例测试记录与保存；
它无法匹配真实 HDMI 目标，因此没有发送 SCDC 读取。
G95 上成功的 SCDC 读取仍未验证。
SCDC 配置和锁定标志仅是观察结果，不能确认实际 DSC 活动或稳定的协商链路。

Claude Opus 在 `107ab64` 审核了 SCDC 更改。
后续修改将两秒读取时限与 500 ms 采样间隔分开处理，
在复核前刷新目标映射输出、接受可选速度/端口规范化、区分不可用与歧义目标，
并在没有 SCDC 观察时保持摘要/状态描述准确。
合成慢读取和规范化输出回归测试覆盖这些路径。
尚未观察 G95 上实际驱动的规范化行为。
关于辅助程序重复、负载大小和假设直接 x86 调用方的审核意见未被认定为当前缺陷。
Claude 报告其只读工具限制使其对已删除行为的检查有限；Codex 也检查了精确差异。

<a id="interrupted-recording-and-internal-display-checks"></a>

## 中断记录与内置屏幕检查

测试覆盖报告就绪前保存启动数据、独占会话锁、中断的最终保存、保留时间线中已完整保存的部分、
未完整写入的条目、归档重试、有界扫描、已完成记录历史、隐私和重复恢复。
端到端测试使用合成显示器，在保存三个样本后终止了由测试启动并管理的记录器进程。
启动时，应用将这三个样本完整恢复到包含部分结果的 ZIP，省略最后一条未完整写入记录，
保留原始文件并排除私密显示日志。没有引发实际硬件崩溃。

正常和最小宽度下的只读 WPF 检查验证了恢复通知和文件夹操作、
已连接和旧的内置屏幕说明、Patch/Restore 禁用状态，以及展开的诊断。
独立审核发现已完成历史记录可能占满扫描限额，导致后面的中断记录得不到处理；
128 个已完成会话之后跟随一个中断会话的回归测试确认了修复。
从未写入存储的硬件遥测和观察结果无法在崩溃后重建。

## 已保存 EDID 的比较检查

测试区分与原始数据、预期补丁完全相同的情况，以及序列号字段、未修改的扩展块和 EDID 长度等额外变化。还覆盖备份无效、缺失、无权读取或存在多个候选项、外部覆盖值、已有旧版备份验证、输入数据保持不变，以及 Restore 条件保持不变的情况。录制测试确认 ZIP 与 Copy details 包含同一份隐私处理后的比较报告。

使用合成数据，在正常和最小窗口宽度下检查了展开诊断区中的完全匹配、其他变化和无法比较三种报告。独立审查未发现需要修复的问题。未写入覆盖值，也未重新连接受影响的显示器；G95C 黑屏的原因仍未确定。

## 单次录制的信号和事件信息检查

测试覆盖精确目标的信号时序、颜色编码和位深、显示路径 GPU、各查询独立失败、适配器名称读取重试、歧义路径、有界 WER 分类，以及序列化和中断恢复的隐私处理。适配器名称读取失败不会阻止 SCDC 采集。WER 输出仅保留 LiveKernelEvent 或 BlueScreen 及长度受限的原始文本问题代码。

在正常和最小窗口宽度下检查了展开的录制信息和诊断。手动填写的显示器 Adaptive Sync 设置默认为 Unknown。一次只读本机扫描返回了开发机器的显示路径 GPU、RGB、每通道 10 位及完整信号时序，未执行 SCDC 事务或更改显示设置。独立审查未发现剩余的可操作缺陷。这些检查没有重现 G95C 黑屏。

## 0.3.3 录制目标与采集覆盖检查

回归测试覆盖不同的已保存和活动 Windows 实例、同名显示器、仅对精确选定目标读取 SCDC、歧义目标、保持修补目标不变、已持久保存样本的计数、独立查询失败，以及从恢复前缀生成的采集警告。Release 构建无警告和错误。

使用合成显示器，在正常和最小窗口宽度下检查了刷新后的目标选择、开始前目标消失、采集缺失或无法确认、采集恢复、停止并保存及最终缺口警告。录制基线对应明确选择的活动实例，Patch 和 Restore 仍使用原有的已保存连接。修复无关路径失败影响覆盖判断及提示文字过时的问题后，独立审查通过。该检查没有执行硬件查询、SCDC 事务、覆盖写入或物理重连，也未验证 G95C 黑屏是否稳定恢复。
