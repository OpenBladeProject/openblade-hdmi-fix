<a id="how-the-patch-works"></a>
# Как работает Patch

[English](../technical.md) | [简体中文](../zh-CN/technical.md) | Русский

Windows хранит экземпляры мониторов в
`HKLM\SYSTEM\CurrentControlSet\Enum\DISPLAY`. Приложение перечисляет эти сохранённые
записи, включая отключённые мониторы, а затем читает `Device Parameters\EDID` каждой
записи. Список присутствующих мониторов из SetupAPI предоставляет метку подключения.
Если получить этот список не удаётся, изменение данных отключается.

Patch принимает монитор любого производителя и модели, если он содержит один блок
HDMI Forum VSDB с OUI `0xC45DD8`, поддерживает DSC 1.2 и имеет код 5 в обоих полях FRL.
Приложение проверяет заголовок EDID, кодировку производителя, точное число расширений,
контрольную сумму каждого 128-байтового блока и границы блоков данных CTA. Производитель
и продукт, декодированные из EDID, должны совпадать с выбранным сохранённым экземпляром
Windows. Для каждого подходящего монитора показывается предупреждение об отсутствии
проверки: ни одна модель монитора физически не проверена с этим приложением. Несколько
блоков Forum, альтернативный Forum SCDB, усечённые данные и неожиданные пары скоростей
отклоняются. Код 4 в обоих полях отображается как уже установленное ограничение.

Нулевое смещение блока данных CTA означает отсутствие блоков данных и подробных
дескрипторов синхронизации. Новое применение Patch требует нулевого заполнения в этом
расширении и никогда не интерпретирует его как возможности. Проверка резервной копии со
схемой версии 1 сохраняет прежнее поведение анализатора при нулевом смещении только для
восстановления существующего точного двухполевого переопределения SAM7463. Резервные
копии других мониторов используют строгий текущий анализатор. Этот совместимый путь не
может разрешить новое применение Patch; для восстановления по-прежнему требуются
идентичные сохранённые EDID и переопределение.

В структурированном блоке Forum старшие полубайты по индексам 7 и 12, считая заголовок
блока CTA, меняются с 5 на 4. Младшие полубайты не меняются. Patch также пересчитывает
контрольную сумму содержащего этот блок расширения. Все остальные байты остаются без
изменений, включая основной EDID, физический адрес HDMI, флаги и параметры DSC, тайминги,
HDR, звук, VRR и неизвестные расширения.

Определения полей сверены с
[анализатором EDID Linux DRM](https://github.com/torvalds/linux/blob/master/drivers/gpu/drm/drm_edid.c).
Это справочный источник по реализации, а не свидетельство стабильной работы дисплея
в Windows.

<a id="override-scope"></a>
## Область переопределения

Приложение записывает только изменённое расширение как одно пронумерованное 128-байтовое
значение `REG_BINARY` в `EDID_OVERRIDE` точного выбранного экземпляра.
[Microsoft описывает переопределения EDID на уровне блоков](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/overriding-monitor-edids);
неизменённые блоки по-прежнему поступают из EDID монитора. Существующие значения
переопределения отклоняются, если они не совпадают с проверенной записью восстановления
этого приложения. Приложение никогда не заменяет целиком переопределение другой программы.

Сохранённые записи не позволяют надёжно определить физический порт HDMI или адаптер.
Приложение не считает кэшированную запись доказательством прямого подключения HDMI.
Отдельные записи имеют стабильные метки подключения, а выбранный экземпляр показывается
в подтверждении. Новый перечисленный экземпляр требует собственной проверки.
Автоматического повторного применения, перезапуска устройства, подключения монитора или
сброса графического драйвера не происходит.

<a id="administrator-operation-and-recovery"></a>
## Операция с правами администратора и восстановление

Окно WPF работает с обычным уровнем целостности. Для Patch и Restore через Windows UAC
запускается кратковременная копия того же исполняемого файла. Её внутренняя точка входа
принимает только фиксированную операцию, точную идентичность
`DISPLAY\<manufacturer><product>\<instance>`, связанную с кэшированным EDID, показанные
отпечатки EDID и переопределения, идентификатор резервной копии для Restore и SID
запустившего пользователя. Она никогда не принимает корень реестра, произвольную
команду или путь результата.

Дочерний процесс заново строит Patch, проверяет идентичность Razer Blade, снова
подтверждает, что монитор отключён, сверяет показанное состояние и до записи сохраняет
надёжную запись `Prepared`. Хранилище реестра повторяет проверку отключения и ожидаемого
состояния непосредственно перед изменением. Именованный мьютекс обеспечивает последовательное
выполнение операций приложения с правами администратора. Полное состояние переопределения
проверяется контрольным чтением до записи `Applied`; родительский процесс с обычными правами
независимо проверяет его ещё раз.

Значения реестра записываются атомарно, но Windows не предоставляет условной операции
сравнения и замены между независимыми программами переопределения. Не запускайте другой
редактор EDID или средство обновления драйверов во время Patch или Restore. Если
появляются неожиданные данные, приложение останавливается и сохраняет исходное состояние.
Оно не повторяет запись с неопределённым результатом и не перезаписывает сторонние
значения ради принудительного восстановления.

Restore принимает только ожидаемое изменённое состояние, сохранённое исходное состояние
или пустой раздел, оставшийся после прерванного применения. Функция удаляет только
значение этого приложения, а не весь раздел реестра. Неактивный пустой раздел считается
восстановленным, если исходное состояние не содержало значений переопределения. При
наличии других значений или другого EDID функция Restore недоступна.

Резервные копии используют атомарную замену файла и временный файл с принудительной
записью на накопитель. Папка и записи должны принадлежать администратору и не иметь
ненадёжных разрешений на запись или точек повторного разбора. Файлы данных предоставляют
доступ на чтение запустившей учётной записи Windows, администраторам и SYSTEM.
Необработанный EDID и идентичность экземпляра являются локальными данными восстановления;
скопированный диагностический отчёт их не содержит. Сбой процесса может оставить
защищённый файл `.tmp`. Сохраните папку для исследования; временные файлы никогда не
используются как записи восстановления.

При проверке файлов данных вспомогательный процесс применяет явное разрешение на чтение
для запустившей учётной записи даже при наличии прав администратора. При наличии активных записей
другой учётной записи приложение блокирует новое применение Patch и поясняет ограничение доступа,
но позволяет восстанавливать собственные копии текущей учётной записи. При обнаружении
число записей не ограничивается. Предел в 512 активных записей применяется только к
новым резервным копиям и проверяется под мьютексом операции до любого изменения реестра.
Завершённые записи перемещаются в папку `history-` соответствующей учётной записи с теми
же тремя субъектами доступа, что и у файлов данных, и остаются доступными для чтения по
идентификатору. Старые завершённые записи в основной папке не входят в число активных.

GPU, драйвер, микропрограмма монитора и точный вариант ноутбука должны быть указаны в
результатах физической проверки. Обнаружение Razer Blade проверяет область применения,
но не означает, что каждая модель Blade протестирована.

<a id="read-only-connection-diagnostics"></a>
## Диагностика подключения только для чтения

Каждое действие Refresh собирает сведения о компьютере, ключи драйверов присутствующих
графических адаптеров через SetupAPI и активные пути Windows DisplayConfig. Текущие
наблюдения связываются только с полным выбранным экземпляром монитора, а не с кодом его
модели или соседним сохранённым подключением. Действие Copy details использует этот
снимок и не опрашивает и не изменяет устройства повторно.
Список SetupAPI содержит все присутствующие графические адаптеры и их драйверы, но не
указывает, какой GPU обслуживает выбранную цель.

Для точной активной цели DisplayConfig предоставляет ограниченную тактовую частоту пикселей сигнала,
рациональные частоты вертикальной и горизонтальной синхронизации и обновления пути,
активные и полные размеры, порядок развёртки, кодирование цвета и число бит на канал.
Имя обслуживающего GPU определяется отдельно по точному совпадению LUID адаптера этой цели.
Состояние HDR поступает из запроса Windows Advanced Color Info версии 2. Сведения
NVIDIA VRR поступают из установленной системной библиотеки NVAPI с использованием LUID
адаптера DisplayConfig и идентификатора цели. Возможность, запрошенное состояние,
включённое состояние и мгновенная активность VRR — отдельные наблюдения. Если
библиотека отсутствует, запрос не поддерживается, топология неполна или сопоставление
неоднозначно, только затронутое наблюдение остаётся неизвестным.

В отчёт попадают только разрешённые описательные поля и сформированные значения состояния.
Пути интерфейсов устройств и идентичности адаптеров остаются закрытыми данными
сопоставления; серийные номера, необработанный EDID, пути реестра и текст нативных
исключений не включаются. Эти диагностические чтения не влияют на допуск Patch или Restore.

Для неразрешённых активных путей в отчёте сохраняются ограниченные категории ошибок и
числовые состояния. Сопоставление остаётся неизвестным, а независимые точные совпадения
сохраняются. Сбор сведений о компьютере и текущих дисплеях имеет отдельные границы
обработки ошибок, поэтому устранимый сбой необязательного источника данных не может
остановить обнаружение сохранённых мониторов или сохранить устаревшие текущие наблюдения.

<a id="recording-a-connection"></a>
## Запись подключения

**Monitor to record** задаёт цель записи независимо от сохранённого выбора для Patch/Restore.
Текущие варианты берутся из однозначно связанных активных путей HDMI с полными
идентификаторами экземпляров мониторов Windows. Явный выбор текущего подключения позволяет
записать новый экземпляр, не меняя цель операции изменения. Перед записью выполняется новое
сканирование. Если сохранённый экземпляр неактивен, а активные альтернативы есть, для начала
нужен явный выбор. Сопоставление использует полный идентификатор экземпляра без учёта регистра;
название модели никогда не служит основанием для подстановки другого подключения.
Выбор сохранённого экземпляра также позволяет начать при отключённом мониторе и ждать
появления именно этого экземпляра.

Действие Record connection в течение одного фиксированного 60-секундного сеанса опрашивает
полный выбранный экземпляр монитора и активную топологию дисплеев, обычно каждые 500 мс.
Более медленное нативное чтение может занимать до двух секунд в пределах оставшегося
времени записи; частота
опроса подстраивается под такое чтение, а не прерывает его через 500 мс. Записываются
метки времени UTC и прошедшее время, уведомления Windows об экране и устройстве,
наблюдения режима, HDR, NVIDIA VRR и SCDC, поля сигнала и формата точной цели,
обслуживающий её GPU, ошибки запросов и пользовательские отметки пропадания изображения.
Необязательные поля микропрограммы, точной модели монитора, кабеля, адаптера, порта и
настройки Adaptive Sync в меню монитора помечаются как контекст от пользователя и
вводятся один раз. Для Adaptive Sync можно выбрать On, Off или Unknown; состояние никогда
не выводится из телеметрии драйвера. Выбранный точный экземпляр распознаётся при появлении,
в том числе после начала записи при отключённом мониторе. При ошибках чтения,
неполном или неоднозначном сопоставлении состояние подключения и каждое необязательное
наблюдение независимо считаются неизвестными.
Другие дисплеи получают локальные для записи метки; необработанные идентификаторы
экземпляров не записываются.

Предупреждение под индикатором прогресса различает отсутствие выбранного экземпляра и
непроверенное состояние из-за ошибки запроса или неоднозначной привязки. Оно исчезает,
когда запись точно выбранного экземпляра возобновляется. Неразрешённые независимые пути
не отменяют действительное точное совпадение выбранной цели. Счётчики записанных,
отсутствующих и непроверенных отсчётов увеличиваются только после надёжного сохранения
отсчёта во временной шкале. Итоговый результат предупреждает об отсутствии записанных
отсчётов выбранного монитора или о пропусках; сводка включает все три счётчика.
Даже если монитор присутствует в каждом отсчёте, это подтверждает наблюдения только
в моменты чтения, а не непрерывный сбор между ними.

Временная шкала сохраняется по мере работы в папке записи
`%LocalAppData%\OpenBlade.HdmiFix\Recordings`. Действие Stop and save или закрытие окна
останавливает сбор и сохраняет частичные результаты. Во время записи недоступны Patch,
Restore, Refresh и выбор монитора. Запись не меняет EDID, настройки дисплея, драйверы
или состояние устройств.

ZIP для отправки содержит исходный отчёт, временную шкалу, сводку и ограниченные
метаданные событий Windows за время записи. Исходный отчёт содержит те же сведения о
сохранённом мониторе и сравнении EDID, что и Copy details, поэтому отдельный скопированный
отчёт не нужен. Для событий Windows Error Reporting файл `events.json` сохраняет только
точную классификацию `LiveKernelEvent` или `BlueScreen` и ограниченный код проблемы `P1`
как текст, если его формат допустим. Код не интерпретируется как десятичный или
шестнадцатеричный. Содержимое и сообщения событий, ссылки на дампы,
вложения и другие поля отчёта исключены. Ошибочные и ограниченные запросы указываются явно. Отдельный файл
`private/display-log.dat`, собранный установленной в Windows программой `dispdiag.exe`,
может содержать идентифицирующие системные данные и не входит в ZIP. Данные не
отправляются автоматически.

Значения сигнала и пути DisplayConfig не доказывают стабильное согласование соединения HDMI.
SCDC сообщает настроенные регистры, когда они доступны, но ни один источник не доказывает
стабильность согласованного видео, активность DSC или физическое изображение. Поэтому
активность DSC остаётся неизвестной. Экран может погаснуть без уведомления об изменении топологии Windows;
пользовательские отметки сопоставляют видимые пропадания изображения с записанными
наблюдениями. Идентификаторы событий и ограниченные коды проблем не указывают точную
причину тайм-аута GPU.

<a id="read-only-scdc-observations"></a>
## Наблюдения SCDC только для чтения

Действие Record connection пытается читать SCDC только для выбранного, однозначно
связанного активного экземпляра HDMI на GPU NVIDIA. Обычное действие Refresh не читает
SCDC. Цель и путь интерфейса Windows, а также сопоставление дисплея NVIDIA проверяются
до и после сбора; для неразрешённых, клонированных, не относящихся к HDMI и изменившихся
целей возвращаются неизвестные наблюдения.

Средство чтения использует установленную системную библиотеку NVAPI из System32 и
общедоступные интерфейсы преобразования идентификатора дисплея и чтения I2C. Каждая
транзакция читает один байт с адреса SCDC в одном из трёх фиксированных регистров:
Sink Version (`0x01`), FRL configuration (`0x31`) и status flags (`0x40`). Составная
транзакция I2C выбирает адрес регистра, а затем читает его байт; значение конфигурации
не отправляется. Средство никогда не подтверждает флаги обновления, не очищает счётчики,
не меняет скорость соединения, не начинает обучение и не вызывает I2CWrite.

Наблюдения временной шкалы включают версию приёмника SCDC, настроенные код FRL, число
линий и скорость, маску синхронизации линий и флаг готовности к обучению, когда их удаётся
прочитать. Это наблюдения регистров, а не доказательство активного видео, стабильного
согласования или активного сжатия. Нулевой код настроенного FRL не доказывает, что
используется TMDS. Активность DSC всегда остаётся неизвестной, поскольку общедоступный
API не предоставляет метода для чтения этого состояния.

Определения регистров и скоростей сверены с
[исходным кодом HDMI NVIDIA](https://github.com/NVIDIA/open-gpu-kernel-modules/blob/main/src/common/sdk/nvidia/inc/ctrl/ctrl0073/ctrl0073specific.h)
и [определениями скоростей FRL](https://github.com/NVIDIA/open-gpu-kernel-modules/blob/main/src/common/inc/nvHdmiFrlCommon.h).
Смысл флагов синхронизации линий и готовности к обучению описан в
[интерфейсе приёмника HDMI Altera](https://docs.altera.com/r/docs/683798/26.1.1/hdmi-ip-user-guide/sink-interfaces?contentId=gS~IsdSbu68mvwyCbk9dpg).
Транспорт описан в [NVAPI I2CRead](https://docs.nvidia.com/nvapi/group__i2capi.html).
Наличие API не гарантирует, что конкретный драйвер или монитор предоставляет SCDC.
Успешное чтение SCDC на G95 не проверено; неудачные, неподдерживаемые и превысившие
время ожидания чтения остаются неизвестными, а остальные данные записи сохраняются.

<a id="interrupted-recording-recovery"></a>
## Восстановление прерванной записи

Средство записи сохраняет исходный отчёт и начальные метаданные до сообщения о начале
записи. Каждый элемент временной шкалы принудительно записывается в хранилище.
Исключительная блокировка сеанса удерживается во время записи и завершения; другой
экземпляр приложения пропускает такой сеанс. При запуске ограниченная процедура
восстановления проверяет неактивные папки записей и создаёт отдельный частичный ZIP из
действительных сохранённых данных. Она не выполняет запросы дисплеев или SCDC, не
повторяет операции и не пытается определить причину прерывания.

Восстановленные счётчики используют только очищенный от закрытых данных префикс временной
шкалы с полностью сохранёнными элементами. Приложение и восстановленная сводка сохраняют
предупреждения об отсутствии записанных отсчётов выбранного монитора или о пропусках;
несохранённый остаток не входит в подсчёт. Незавершённый последний элемент временной шкалы исключается. Исходная временная шкала и
незавершённый архив остаются на месте. Восстановление исключает незнакомые файлы,
закрытые журналы дисплеев и идентификаторы сопоставления, а отсутствующие итоговые данные
отмечает как недоступные. Оно не подставляет вымышленное последнее показание или метку времени
завершения работы. При внезапном отключении питания накопитель всё равно может потерять
последние записи; программная принудительная запись не гарантирует, что эти байты
сохранились.

## Сравнение EDID с резервной копией

При Refresh приложение сравнивает доступный сохранённый EDID с проверенной активной резервной копией для того же экземпляра монитора в Windows. Полный ожидаемый EDID после патча восстанавливается из исходной копии и проверенных блоков переопределения. Сравниваются длина и все байты, включая блоки, которые патч не меняет. Совпадение установленного переопределения проверяется отдельно.

Отчёт различает точное совпадение с исходными данными, точное совпадение с ожидаемым результатом патча, другие изменения и недоступное сравнение. Совпадение всего EDID и установленного переопределения с патчем согласуется с сохранением данных патча в кэше Windows. Оно не показывает, какие данные использовал драйвер, и не устанавливает причину пропадания изображения. Для обоих эталонов приводятся номера блоков и количество изменённых, добавленных или удалённых байтов. Исходные байты, значения серийных номеров, полные хеши и идентификаторы резервных копий не публикуются.

Copy details и исходный отчёт записи подключения используют результат одного сканирования. Если копия отсутствует, закрыта для текущего пользователя, повреждена или есть несколько подходящих записей, приложение указывает причину и не подставляет данные другого монитора. Сравнение служит только для диагностики; проверки Patch и Restore остаются прежними.
